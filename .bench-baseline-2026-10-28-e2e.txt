=== End-to-end floor (T2 warm/cold + T2-native), recorded 2026-10-28 ===

What this file is. RECORD-ONLY history of the end-to-end tiers: the absolute
medians each end-to-end speed item is measured against, so its gain is visible
in this file's history. It is NOT a verdict. The `e2e-gate` job of
.github/workflows/bench-gate.yml decides by a same-run paired A/B of the base
and candidate `mindc` (tools/bench_gate.py --pairs, rule in
docs/benchmarking.md) and only RECORDS the candidate against these rows, in a
continue-on-error step read with `--floor-prefix ''` (every row below is a full
criterion id). It is separate from .bench-baseline-2026-06-01-correctness.txt,
which guards the frontend (T1) budget and is unchanged. Tiers are defined in
docs/benchmarking.md.

What was measured. The compiler is origin/main ecd8be99, i.e. BEFORE the
end-to-end speed work (runtime-object cache switch, tool-identity memo, native
front-end work). `mindc` is a release build (`cargo build --release --features
"mlir-build std-surface cross-module-imports"`), LLVM 20.1.8 (`mlir-opt`,
`mlir-translate`, `clang`).

  - e2e_compile_shared/warm/<shape>: `mindc src --emit-shared out.so` with the
    runtime-object cache primed.
  - e2e_compile_shared/cold/<shape>: the same with a fresh, empty
    XDG_CACHE_HOME per run (and MINDC_RUNTIME_OBJ_CACHE=0).
  - e2e_native/<shape>: `mindc build --backend native src --out elf` from the
    repository root, on the pinned backend_native_bridge corpus; every output
    was byte-identical to its committed oracle ELF.

How. A wall-clock harness (one spawned process per sample), 40 timed runs per
row after 2 untimed rounds, every row interleaved in a per-round shuffled order
in ONE session, on a Linux x86-64 build host, 4 pinned physical cores. The
value on each row is the MEDIAN. Spread is given as p10/p90 beside each row.
The release mindc built from this commit and from origin/main are
byte-identical (same sha256), and both were timed in the same session as an
A/A control: their medians differ by at most 7.1% (local_call), all other rows
within 3.6%.

Why record-only. The same commands on the same host measured 18-31% apart
between sessions with load (MIND and reference rows alike), three times the
+10% regression the gate exists to catch; and against a hosted runner an
absolute build-host number means nothing. A floor wide enough never to trip on
load could not catch +10%. So no verdict is ever taken from these rows: the
paired A/B decides, and these rows only record history. Re-record them on the
build host, never from a hosted runner.
