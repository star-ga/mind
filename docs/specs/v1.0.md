## 2. Types (Tensor[T, Shape], device placement, effects)
### Phase 3A subset
- `ValueType`: `Scalar(i32)` and `Tensor(TensorType)` (tensor placeholder for future phases).
- Literals: `Int` → `Scalar(i32)`.
- Identifiers: resolved from the type environment.
- Binary `+`, `-`, `*`, `/`: require both operands `Scalar(i32)`; result `Scalar(i32)`.

### 2.1 Primitive scalar table (normative)

Each primitive scalar type resolves once, at its declaration, to one row of
this table. The type code is the position of the name in the list
`i8 i16 i32 i64 u8 u16 u32 u64 isize usize bool f32 f64`. A consumer (a
narrow-width rule, an extern signature, a struct field size) reads the row,
never the spelling. `bool` is one byte (C `_Bool`). `isize` and `usize` are 64
bits on every accepted target.

| code | name | bits | signed | bool | class |
|------|------|------|--------|------|-------|
| 0 | `i8` | 8 | yes | no | INT |
| 1 | `i16` | 16 | yes | no | INT |
| 2 | `i32` | 32 | yes | no | INT |
| 3 | `i64` | 64 | yes | no | INT |
| 4 | `u8` | 8 | no | no | INT |
| 5 | `u16` | 16 | no | no | INT |
| 6 | `u32` | 32 | no | no | INT |
| 7 | `u64` | 64 | no | no | INT |
| 8 | `isize` | 64 | yes | no | INT |
| 9 | `usize` | 64 | no | no | INT |
| 10 | `bool` | 8 | no | yes | INT |
| 11 | `f32` | 32 | yes | no | FLOAT |
| 12 | `f64` | 64 | yes | no | FLOAT |

## 3.3 Conversion from float to Q16.16
- A Q16.16 value is a signed 32-bit integer `q`. Its numeric value is `q / 65536`.
- The conversion `Q(x)` takes a binary64 value `x`. A binary32 value widens to binary64 first. This step is exact.
- A float literal becomes a binary64 value first (nearest, ties to even). `Q` uses that value.
- Let `s` be `x * 65536` as an exact real number. Let `r` be the integer nearest to `s`. If two integers are equally near, `r` is the even integer.
- The result is in range when `-2147483648 <= r <= 2147483647`. Then `q = r`.
- Constant conversion: the compiler refuses the program if `x` is NaN, `x` is infinite, or `r` is out of range. The compiler writes no artifact.
- Run-time conversion: NaN gives `0`. `+inf` or a too-large `r` gives `2147483647`. `-inf` or a too-small `r` gives `-2147483648`.
- The conversion does not trap. The conversion does not wrap. `-0.0` gives `0`.
- An integer literal `n` in a Q16.16 literal has the numeric value `n`.
- The conversion is explicit: a Q16.16 type annotation on a literal, or the cast `as q16`. No other float value becomes Q16.16.
- Each compiler route gives the same 32 bits for the same `x`. The dynamic rounding mode has no effect.
- The cast `x as i32` truncates toward zero. It is not a Q16.16 conversion.

## 5. Module System and Stdlib Surface

### 5.1 Import Statements

The `import` statement brings modules and submodules into scope:

```mind
import std.io;
import std.crypto;
import module.submodule;
```

**Syntax:**
- `import <path>;` where `<path>` is a dot-separated module path
- Semicolons are optional but recommended

**Examples:**
```mind
// Standard library imports
import std.io;           // I/O operations
import std.mem;          // Memory management
import std.thread;       // Threading primitives
import std.crypto;       // Cryptographic functions
import std.fs;           // Filesystem access
import std.process;      // Process management

// Multi-level imports
import mylib.utils.helpers;
```

**Semantics:**
- Import statements are processed at module level
- They do not produce runtime values
- Name resolution occurs during semantic analysis phase
## 5.2 Extern bindings

An `extern "C"` block has a binding. The binding tells where the code address
of each function in the block comes from.

```
extern "C" [callconv(.tag)] [bind("<soname>") | bind(.address)] { fn ... }
```

- Write `callconv` first when the block has both clauses.
- No clause: the base binding. The symbols come from the base set of the
  target. For x86_64-linux-gnu the base set is `libc.so.6`, `libm.so.6`,
  `libdl.so.2` and `libpthread.so.0`.
- `bind("<soname>")`: the library binding. The name is the exact name that the
  system loader looks for, for example `bind("libcuda.so.1")`. It has 1 to 255
  bytes from `A-Z a-z 0-9 . _ + -` and starts with a letter or a digit. A name
  in the base set is refused (E2045). One name with two bindings is refused
  (E2045).
- The link adds each declared library once, after the base set, in ascending
  byte order of its name. A declared library is needed when no call uses it.
  The compiler adds no search directory and no rpath. A target with no link row
  for a library (PE/COFF and Mach-O today) refuses the clause (E2045).
- When the link fails and the unit calls base-bound extern names, `mindc`
  reports E6012 with these names. No artifact is written.
- `bind(.address)`: the address binding. Each declaration is a C prototype. It
  binds no symbol and links no library. A call is `name(addr, a0, ..., aN-1)`.
  `addr` is the code address. The other operands are the declared parameters,
  with the same checks as a direct call. Another operand count is refused
  (E2005). Varargs in the block is refused (E2045).
- If `addr` is 0, the process exits with status 78 and writes nothing.
- Narrow arguments of an address call extend to 32 bits by their declared row:
  `i8` and `i16` sign-extend, `u8`, `u16` and `bool` zero-extend.
- A call through an address is always unclassified for determinism. The
  evidence labels the artifact `nondeterministic`. `dlopen`, `dlsym`,
  `dlclose` and `dlerror` read the host loader state. A program that calls one
  needs `--allow-nondeterministic`. Code that a program loads at run time is
  outside the attested artifact. The evidence names the declared signature and
  marks the call. It does not attest the loaded code.
- The evaluator (`mindc run`, `mindc test`) refuses an address call (E2045).
- 0.10.3: the MLIR route only. The native route (`--backend native`) refuses
  each `bind` clause as `lane.extern.bind_clause` (exit 3, no artifact).
- mic@3 carries a non-base binding in one `OP_EXTERN_BIND` record (0x2C)
  directly after its declaration. A base binding writes no record.

## 7. Safety, Errors, Diagnostics

### Phase subset (Diagnostics)
- Errors report 1-based line/col and a single-line caret highlight.
- Multi-line spans degrade to single-line best-effort (to be improved later).

## 7.1 REPL (Phase subset)
- Stateful environment: variables persist across inputs.
- Input is parsed as a mini-module (statements separated by `;` or newline).
- Result = last statement/expression value.

## 2.1 Shape Inference (Phase 1)
Left-biased unification:
- Known==Known → Known
- Known↔Sym → Known
- Sym↔Sym → left symbol
- Rank mismatch → missing dims become `UNK` (left-biased)

## 5.1 Stdlib (Phase 1)
`Tensor<T>` placeholder with `zeros/ones/reshape/shape/sum/mean` (no storage).

## 4. Typing (Phase 3A subset)
- `ValueType`: `Scalar(i32)` and `Tensor(TensorType)` (tensor reserved for later).
- Literals: `Int` → `Scalar(i32)`.
- Identifiers: resolved from type environment.
- Binary ops `+ - * /`: both operands must be `Scalar(i32)` → result `Scalar(i32)`.

## 4.2 Type annotations (Phase 3B)
- `let name: i32 = expr`
- `let name: Tensor[dtype,(dims...)] = expr` where `dims` are ints or symbols.
- Annotation seeds the type environment and is validated against the inferred type of `expr`.
- For now, expressions type-check only as scalar arithmetic; tensor annotations are enforced but tensor arithmetic is not yet implemented.

## 4.3 Tensor binary ops & broadcasting (Phase 3C)
- Dtype: `Tensor[f32, S] ⊕ Tensor[f32, T]` → `Tensor[f32, broadcast(S,T))`.
- Scalar promotion: `Scalar(i32) ⊕ Tensor[f32,S]` → `Tensor[f32,S]` (type-level promotion).
- Broadcasting: right-aligned; dim matches if equal, or one is `1`. Symbols must match exactly, or match with `1`.
- On mismatch (dtype or shape), emit type error.
